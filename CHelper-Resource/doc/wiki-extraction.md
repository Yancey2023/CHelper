# 从 Wiki 提取命令说明

处理顺序：下载原文 → 应用少量原文 patch → 提取参数与选项 → 匹配现有节点 → 打包。
`resources` 中的命令 JSON 提供节点类型、连接关系、别名和各版本语法；自动提取
只更新说明及 brief，不建立同义的新节点。

外部原文来源限定为中文 Minecraft Wiki。缺少说明时可以采用维护者授权的人工补充
patch，并明确记录补充理由。英文 Wiki 和官方文档原文不作为 description 的补充来源；
中文相关页面或历史版本的引用应保存网址、版本和原文。
只查过命令页时，不能据此宣称整个中文 Wiki 都没有该信息。

## 页面与维护文件

| 文件 | 用途 |
| --- | --- |
| `output/command_wiki/<command>/page.wiki` | 未修改的 Wiki 原文 |
| 同目录 `source.json` | 页面地址、抓取状态和重定向 |
| `data/wiki_patches/<command>.json` | 需要规范化的少量原文改动 |
| `data/wiki_patches/game_rules.json`、`data/wiki_patches/<edition>/game_rules.json` | 中文《游戏规则》表的通用及版别来源 patch；依次应用后提取 ID 说明 |
| 同目录 `patched.wiki` | 应用 patch 后用于提取的页面 |
| 同目录 `extracted.json` | 参数、枚举、brief、原文行和解析警告 |
| `output/command_docs/<edition>/<branch>/<command>.json` | 可审阅的资源提案 |
| 同目录 `<command>.sources.json` | 逐字段匹配来源及缺失/警告 |
| `output/command_docs/index.json` | 覆盖、patch、原文哈希和完整性汇总 |
| `output/command_docs/generated_catalogs/<edition>/<branch>/` | 完整生成时真实 ID 集合的目录提案与逐项来源；包括新 ID 缺项诊断 |

## 固定枚举句式

“必须为以下其中之一：”是枚举对象的结构标记，在原文中保留，提取时关联其后
的选项列表。各选项的原文说明对应资源里的枚举项，true/false 对应 Boolean 两态。
这段引导句不作为节点 description 的用途说明。

已有固定句式的页面无需为这段文字写 patch。其他枚举句式或不明确的 Boolean
条件句，通过最小原文 patch 规范成固定引导和明确的选项列表，再交给相同解析规则。
patch 不改变原文实际行为、数值或版本能力；保留改动理由与来源依据。
优先复用 Wiki 原文。按维护者2026-10-15的新授权，原文缺少用途说明时，由 Luna
编写简短中文人工补充，以最小 patch 加入对应参数或选项；每条补充规则的 reason
必须标明“人工补充”及语义范围，不冒充 Wiki 原句。原始 page.wiki 保持不变，
来源报告同时导出 patch_reason、按规则顺序排列的 replacement_reasons 及前后哈希。
外部参考仍限中文 Wiki，不引用英文 Wiki 或官方文档原文。参数改名和上下文歧义
优先通过最小 patch 整理真实参数名、别名、版别标题和语法说明，再自动匹配。
同一概念的组合参数可以共用标题、完整用途说明和 brief；不同职责的参数不能为
迁移而强行合并。不得把 JSON pointer、行号选择器或另一套 binding 语言搬入原文。
来源维护仅使用原文 patch，不另设字段绑定或目录注册。原文结构无法消歧时，
先补齐自然上下文、关键词用途或真实参数定义，再重新提取；不在 Rust 中写命令字段表。

patch 按顺序精确匹配并校验命中次数；上游原文变化导致匹配失败时会报错，
reviewer 应重新检查页面，不能弱化匹配规则来绕过漂移。
游戏规则表在各版共用原文时，也先使用相同的精确 patch 机制，再提取描述。
版别差异留在相应目录的原文 patch 中；例如旧网易版不引用其版本不存在的硫方怪。
不在 Rust 中硬编码实体名单，不修改下载缓存，也不将新版本举例直接套入旧版。
命令别名跳转到同一页面时，优先读取别名专属 patch；不存在时可以按缓存的
resolved_title 复用规范命令页 patch，来源报告记录实际文件。别名仍分别提取各自
命令区域，复用 patch 不代表复用整份命令定义，也不降低页面的 patched 统计。
提取中途失败时可能保留上一次的提案和报告；应以本次 CLI 退出状态为准，
只有成功结束的运行才能作为当前结果，不能继续打包旧提案。

同名参数结合资源中实际消费它的语法路径及自然章节上下文选择来源。
主参数名优先于其他参数的次要别名；模板内的 `{{!}}` 按显示含义还原选项分隔符。
原文共用一个段落并不表示多个参数是别名，也不表示整组用途可以逐个复制。
独立节点的 description 和 brief 应解释该输入自己的职责：例如 RGB 三个整数分别
描述红、绿、蓝分量，三个标题时长分别描述淡入、保持、淡出。整组用途与组合行为
保留在真实组合节点、关键词用途或相应语法说明中。需要区分时，通过原文 patch
拆成独立自然参数标题，保留各自用途、单位和区分语法分支的必要上下文；不在提取器中猜测分工。
本身就是单个 POSITION 输入的 `x y z` 不应为了拆分而创建新节点；确实职责相同的
两个输入也无需编造差异。审阅时同时检查子参数与组合节点，避免把共用段落的问题
改成父节点机械堆叠所有子参数说明。
共享关键词应在原文中说明其全部合法用途，不能任取某一个子命令的说明。
自然的定义列表也可以用于关键词和固定值，例如：

```text
; 关键字 <code>list</code>
: 沿用原文、明确各语法条件的用途说明。
```

这些是可阅读的 Wiki 文本，不能填写资源字段路径或额外的机器选择指令。
原始历史和 patch reason 可以记录证据；运行时 description 不保留版本加入、
移除实验等沿革叙述，且不能仅删除日期后把新版本限制无条件套入旧版。

选项支持“ID — 说明”与“中文标签：ID”两种位置关系。简单 Wiki 参数表可按表头
提取选项，并将 rowspan 的槽位限制关联到各实际行；复杂布局不能确定归属时告警。
表格中的中文用途标签进入选项 description，数值范围、适用条件等单独保存为
constraints；不能用约束填补没有原文的用途说明。
`units` 数组中的元素只匹配单位选项原文，不使用包含同名字符的命令行为句。

平铺的相邻语法形式可以共享原文紧随其后的说明。层级列表只在同层且字面动作
一致时共享，避免把 camera clear、fade、color 等不同动作的说明串在一起。
Boolean 的 `description` 只取简短参数用途；true/false 的核心含义分别写入
`descriptionTrue`、`descriptionFalse`，不生成两态概览，也不使用它填补缺少的参数用途。
按维护者2026-10-29的要求，运行时说明不叙述省略或未指定参数时的默认、失败或查询行为；
通过原文 patch 删除这些补充，保留参数用途和显式取值的效果。若原句同时说明省略与某个
显式值（例如0或-1），先删除省略分支。按维护者随后补充的要求，
默认值相关描述也全部删除，包括“默认为50”、独立默认数值、“默认采用”和“（默认）”标签。
保留参数用途、单位和选项本义，不得把类型/默认值模板当作用途说明。语法里的可选结构保持不变。
真正名为 default 的选项及世界设置等概念保留其ID和含义；重置动作保留重置用途，
不因此删除选项或留下空说明。此项不改变实际默认值数据和执行行为。
普通枚举概览保留值标签，使互斥条件仍可辨识。

按维护者2026-10-29的进一步要求，运行时 description 只保留用途和选项的核心本义，
删除合法取值范围、上下界、越界裁剪或回退、格式及目标合法性等限制性补充。例如页码
只说明“指定要展示的命令列表的页码”，不再说明小于1或超过总页数如何处理。
参数自身表示最大范围、半径等时仍说明其用途；单位、方向和区分不同语法职责的上下文
保留。Boolean 两态和枚举选项的真实效果不可为清理限制而删除。原文固定枚举引导仍供
提取器识别，不进入运行时用途。此项只简化文案，不修改节点的 min/max、类型或语法。

维护者随后要求对全部介绍逐项评估冗长程度：参数说明通常只需一句用途和必要单位，
不再附带单位例外、特殊0或-1行为、例子、次要副作用和长列表。这也覆盖此前保留特殊值
附注的策略。例如效果时长只保留“以秒为单位指定效果时长。”，不附瞬时效果例外和0秒
移除效果的说明。独立Boolean或枚举值仍各有简短核心含义；真实组合输入用短句涵盖各
组成职责，不机械堆叠子参数全文。不能按字数或首句自动截断，需逐字段判断最短且完整的
用途，并保留避免语法职责混用所需的上下文。brief及全部非文案结构保持原值。
execute保持既有固定结构和节点定义，其根简介可在原固定patch内精简，不重建节点。

gameMode 外置目录的定义及别名也从 gamemode 参数选项提取，提案和逐项来源保存于
`output/command_docs/catalogs`；提案与运行包复用同一 normal-ID 格式（id/type/content）。
命令现有节点中的 ID 引用与对应参数的封闭枚举共同决定需要提取哪些外置目录。
固定枚举引导句或明确“见下表”的参数表是完整性校验的依据，示例不自动变成目录。
来源命令不存在的版别、没有实际引用的旧目录不参与。相同目录由多个命令消费时，
聚合它们有明确归属的选项；用途冲突仍作为缺项，不能任取其中一句。

自然声明 `本命令不支持的值：<code>value</code>。` 只排除原文明示不适用的值；
任一有效消费来源支持该值时仍保留它。其余新 ID 必须有用途来源，缺项或排除后为空
均阻止发布。不能用删除目录、只校验维护快照或保留旧猜测来掩盖新 ID 的缺失。
目录报告中的排除项与原文行都是提取结果，不是需要人工维护的选择配置。

`generate` 对真实新生成目录再运行相同检查。未知项会清除提案中的旧说明并计入
`unresolved_catalog_fields`；命令缺项计入 `unresolved_fields`。其他不具备封闭
Wiki 枚举的外置 ID 仍由原数据管线生成，不能把这一机制称为全部 ID 都已有 Wiki 定义。

## brief

brief 用于结构化命令里的短中文参数名。默认从参数用途说明提取：例如
“指定相机视角朝向的实体。只在使用……时有效。”得到“相机视角朝向的实体”。
解析器不另外用 AI 起草摘要。

默认 brief 太长、不适合作为参数名，或原文没有可提取的短中文名时，
可以在 patched Wiki 的对应参数块末尾追加自定义标签：

```text
: brief：朝向实体
```

提取 description 时跳过该行，提取 brief 时使用它。`max_brief_chars` 默认为12，
按 Unicode 字符计数，超过阈值输出命令、参数、原文位置及长度警告，提示自定义。
自定义 brief 仍超过阈值时也会告警，不静默截断。
自定义标签是明确允许的维护元数据，不能混入 description；不因普通长度警告
给每个页面都增加 patch。brief 的字段来源会区分 `brief-explicit` 和 `brief-derived`。
由语法组合出的节点也可以在对应语法说明末尾使用同一 brief 指令。
没有参数 brief 候选时，自动匹配可使用同名字面动作的语法 brief；多个不同候选
仍视为歧义，不随意选择。该指令不会进入语法 description。

## 审阅和运行

事实复核需要逐项比较迁移前注释、本轮修复前字段、中文 Wiki 的语法/参数/结果/版别
上下文及修复后实际JSON。不同时间点应分别标注，不能拿中间文案冒充历史提交原句。
检查目标数量、执行主体、动作结果、Boolean两态、单位和条件；共享动作需覆盖其全部
合法分支，不能把带有特定选择器的示例当作通用目标范围。Wiki原文也可能存在概述与
语法/结果矛盾，应核实后用最小patch修正，不能只因逐字提取就判为事实正确。

只审阅实际版别存在的节点；Java专属候选不应被算成基岩版缺失字段或修复成果。
节点类型本身也不能证明游戏支持该行为，需结合版别原文与示例。缺失字段为0、文件
哈希相同及打包/测试通过各自验证提取与实现，不能替代语义复核。
本轮方法和具体修复见 [2026-10-23事实复核](command-review-2026-10-23.md)。

Wiki 与 JSON 的扫描、字段来源匹配和必要 patch 由 gpt-6-luna 子 agent 负责。
先用本地缓存生成提案：

```powershell
chelper extract-command-docs
chelper extract-command-docs --commands alwaysday,difficulty
```

`--apply` 仅在全部命令和自动关联目录字段来源明确时写回该批维护源；
缺失字段时保留提案和报告，不执行写回。`generate` 自动运行相同提取流程，
有未解决的命令或目录字段时拒绝资源包导出。警告用于指明需要复核的位置，不允许靠保留旧 AI 文案冒充已提取。

未知且可能提供可见文字的介绍模板会造成来源缺失，不能静默删词后算完整。
experiment 模板可保留中文 Wiki 原文中的稳定 ID，以反引号标作代码；尚未核实
本地化显示名时明确告警，不猜译名。简介保留共通用途；具体支持条件依据现有
语法及参数原文表达，不靠加入/移除实验的历史叙述补字段。

页面的教育版可用性、独占范围和草稿状态保存在 `page_metadata`，不拼入用途说明；
教程导航等已识别的页面元数据也不会成为 description。带 `for=` 正文的条件模板
仍按其内容和作用范围解析，不能当作横幅整段删除。

资源生成先写入正式输出目录旁的独立临时目录，所有生成和来源检查成功后才替换
正式输出。失败会保留原资源包，替换失败时尝试恢复原目录；只生成部分版本时保留
未选择版本。正式输出目录只允许包含生成器管理的 release、beta、netease 和
old2new 目录，包含其他内容时拒绝整目录替换。Wiki 缓存、提案和未翻译清单等辅助
信息仍可能在失败时更新；判断发布成功必须以本次 CLI 退出状态为准。

按项目要求，execute 的固定 REPEAT 入口和原说明由既有 patch 保留。
独立的 repeat、grammer 和 JSON 组件定义继续保留其维护源，不被命令参数提取覆盖。
