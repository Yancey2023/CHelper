# 成本与设计取舍

本页记录 CHelper-Core 的接口约定和实现判断。必要的是正确语义，具体数据结构和编码仍可优化；当前写法不因通过正确性测试就成为唯一或最快方案。性能结论及未合入候选见[性能审计](performance-audit.md)。

## 生命周期与资源

| 约定                       | 实现要求与成本判断                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 工厂返回原始指针           | 对象生命周期由外部管理，调用方自行选择显式释放或 RAII；不为统一风格迁移公开所有权                               |
| 补全和文本视图借用已有数据 | 不为独立生命周期复制内容。补全结果及其复制引用须先于 context 销毁；shared_ptr 不保证单独保活底层 PMR 池         |
| CPack 只保留加载期资源     | createContext 不向 CPack 资源分配；context 资源只用于构造时解析，查询和 applySuggestion 不使现有 arena 持续增长 |
| 容器记录实际分配资源       | 不替换进程 PMR 默认资源，销毁不依赖线程当时的资源路由。自定义资源须覆盖对象及相关弱引用的生命周期               |
| 类型安全的 ID 访问         | 不能把派生类容器整体转换成基类容器。安全语义应保留，额外数组和逐 ID 引用不是唯一实现，替代视图须遵守借用约定    |
| 发布后只读                 | 资源绑定、哈希预热和静态节点初始化在发布前完成；额外预热有加载成本，适合多次查询场景，不保证所有用途更快        |

具体所有权和并发使用方式以 [Core 开发说明](../README.md#c-接口与所有权)及 [CommandContext 接口](../src/chelper/CommandContext.h)为准。只读方法不意味着调用方可以同时修改资源或释放正在使用的对象。Old2New 修复表由调用方串行初始化，再发布给转换调用。

## 校验、匹配与格式

| 项目                   | 判断                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 内部范围、类型等不变量 | 按可信调用约定处理，调试检查放在 CHelperDebug 下；避免查询热路径反复防御已保证的条件                                                         |
| 原始字节和文件边界     | 保留损坏／截断输入、尾部字节、文件打开与写出失败的检查；这类边界可能真实失败                                                                 |
| Grammar 图校验         | 当前加载器拒绝空组合、重复 ID 和不消费输入的递归；合法递归不设深度预算。自维护资源可评估把完整校验前移到生成阶段，调整时需同步入口契约和测试 |
| ID 匹配                | 按 XXH3 64 位摘要匹配，不追加字符串比较；哈希碰撞是项目接受的取舍，不宣称数学上无碰撞                                                        |
| 补全去重               | 保留名称长度、范围、描述存在性和空格行为的区分；字段语义不能删，编码方式和范围临时数组可以优化                                               |
| 二进制兼容             | 保持 .cpack 布局、字段顺序和节点类型编号；新增类型在登记表末尾追加，不插入重排                                                               |
| JNI                    | 边界处理异常、保留已挂起的 Java 异常，及时释放局部引用并处理真实分配失败；内部已保证条件不重复校验                                           |
| Web                    | 调用方与实现一同发布，维持轻量协议，不增加 nativeError 或协议版本握手；JS 在下一次结果调用前读取借出的结果缓冲区                             |

相关实现入口：[资源路由](../src/chelper/util/CPackMemory.h)、[语法校验](../src/chelper/node/GrammarValidation.h)、[补全摘要](../src/chelper/auto_suggestion/Suggestion.cpp)、[节点类型登记](../src/chelper/node/NodeWithType.h)。

## 开发工具与验收

资源审计、全局分配钩子、sanitizer、fuzz 和逐样本记录各有用途；仅在对应选项关闭且构建一致时，才能把结果视为普通发布路径的计时。计时和分配观察分开，操作方法见[基准测试](benchmarking.md)。

避免越界、悬空引用、跨资源释放及错误的所有权是必要语义，不能靠泄漏换取较低耗时。必要语义也不等于当前实现的全部成本都必要：改变视图、布局或缓冲区接口时，应分别评估常见查询、加载／销毁、内存保留、并发及平台体积。

当前不接受“所有旧退化都是必要成本”或“所有未复现差额都是噪声”的概括。未通过相应平台延迟验收的原型继续作为候选，不把局部指令、栈空间或某轮中位数的改善当作整体收益。
