# 性能审计

整理日期：2026-11-05。以下结论来自 2026-11-02～03 保存的实验；本次文档整理没有重新计时。原始数据及阶段报告见[历史归档说明](README.md#历史归档)。

## 当前结论

已找到并修复部分不必要开销，也确认了尚未修复的 WASM 深嵌套栈问题。历史性能差额仍未全部唯一归因，现有证据不足以宣布整体性能全面改善或全面退化。

旧报告的数字有保留日志支持，但其构建身份、资产时点、输出精度和运行条件各有限制。它们是对应轮次的观测，不能直接作为当前版本或单项改动的成本。嵌套样本的历史 p50 也曾明显增加，不能把全部差额解释成少数离群值或噪声。

## 已确认的问题与成本

| 项目         | 已证明的事实                                                               | 状态与边界                                                                  |
| ------------ | -------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 资源选择遗漏 | 三处构造遗漏曾使目录／二进制加载分别多出 1,274／1,054 次普通堆缓冲区释放   | 已修复；不能据此还原早期每个耗时百分比                                      |
| 补全摘要     | 字段边界、描述存在性和空格行为需要区分；编码会增加操作，也会改变去重表分布 | 保留语义，具体编码可优化；没有因此复制建议文本或追加字符串复查              |
| 查询缓冲区   | 真实释放／重新分配伴随撤销提交、重新提交及缺页，不链接 Core 的回放也可复现 | 调用方复用容器是可评估方案；不能用现有 CPack/context arena 持续增长掩盖成本 |
| WASM 深嵌套  | 递归解析、结构收集和 AST 销毁消耗调用栈；指定路径耗尽默认 64 KiB 栈        | 修改前已存在，尚未完整修复；没有添加人为深度上限                            |
| Android 体积 | 旧资产跨多个源码提交未更新；同配方源码对照的本轮净增为 12,336 B，约 +0.88% | 旧资产到当前库约 +12.3% 不能全部算作本轮成本；体积不代表延迟                |
| 测量工具     | 文本量化、同路径模块缓存、跨 DLL 的 TLS 资源作用域混杂分别有复现与修正     | 各自解释对应实验，不能统一解释正常生产路径的全部差额                        |

## 未合入的实验候选

| 候选                     | 已验证的结果                                                                                        | 合入前仍需解决的问题                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 借用 typed ID 视图       | 可避免额外的逐 ID 所有权；原生语义／资源检查及平台构建已有记录                                      | 延迟验收未完成，ARM64 实验产物净增 13,040 B；不能以少量静态指令代替平台验收 |
| 摘要直接借用对象前缀字节 | 三目标编译及原生／WASM 各 4,096 个差分用例通过；指定 WASM 样本少 64 B 栈峰值，并保留一次范围 update | 依赖编译期布局约定；没有整体耗时收益结论                                    |
| 移出 wrapped 的末尾组装  | 指定路径常驻区域 400 → 304 B，每层增长 2,160 → 1,968 B；代表性 API 查询一致                         | 组装时另有 176 B 临时区域，32 层仍失败；不能当作完整去递归修复              |

这些数字只属于各自的冻结资源、编译配方和实验条件，不是跨设备保证。共享别名所有者原型曾因并发争用被拒绝，JSON 池化原型也存在额外未用容量；均未作为生产优化接受。

## 尚未完成的归因

| 缺口                                 | 当前边界                                                                                |
| ------------------------------------ | --------------------------------------------------------------------------------------- |
| 历史原生补全、嵌套、选择器和销毁差额 | 保留矩阵缺少当时的逐样本系统轨迹，首轮完整构建信息也不全；新对照不能恢复旧现场          |
| 历史 WASM 实例耗时差额               | 原实例状态记录不足，首轮发布资产与源码基线时点不同；新栈容量实验不能抵扣旧微秒数        |
| 旧 Android 资产的精确生产过程        | 旧源码重建仍差 1,200 B，原始 CMake 重建仍差 1,328 B；需要原生产配置、工具或源码备份补证 |

用户目前没有上述旧记录。保留未知不代表已证明没有退化，也不代表剩余成本全部必要。重复新的整体均值不能填补这类缺口。

## 后续工作

优先处理已确认的深嵌套栈问题，覆盖解析继续／回退状态、结构收集和 AST 销毁。仅扩大栈或局部拆函数不能证明问题已解决。

候选优化应保持原有 API 生命周期与资源作用域，在对应平台完成语义和延迟验证后再决定是否采用。接口约定和必要性判断见[成本与设计取舍](change-cost-review.md)，测量入口见[基准测试](benchmarking.md)。
